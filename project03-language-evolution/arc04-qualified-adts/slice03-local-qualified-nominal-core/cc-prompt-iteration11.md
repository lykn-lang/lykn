## Defect and prescribed implementation

Native resolve_seq still extends structural hoisted_names(form) even when its
head resolves to an ordinary call. Thus `(bind array 1)` after a callable bind
binding can falsely put array in scope, changing later `(array 7)` into a call
to a nonfunction. Pass2's actual-result helper already gates this case, but
the later resolver undoes that decision. Structural helpers also miss wrapped
declarations; the public expander helper stops at trusted kernel before it
unwraps export/async. D2 and shadow transition clients use related partial
adapters. Repair the shared policy rather than special-casing the witness.

1. Introduce one private dispatch-aware enclosing-declaration SITES query per
   backend. Its input is the actual form and incoming value scope, its output
   preserves BindingSite kind/name/span (JS node) for diagnostics. Name-only
   consumers project names from those sites. Keep raw bindings_introduced/
   bindingsIntroduced and existing public hoistedNames structural contracts;
   structural binding discovery remains separate from actual state changes.
   No owner context, analysis cycle or new public option.
2. An ordinary bound/tagged head yields no following-sibling declaration sites.
   Native consumes as_form_head plus incoming scope. Public untrusted heads
   follow existing binding-tag/incoming Set policy; real isKernel provenance
   retains dispatch priority. Never spread a wrapper's trusted status to an
   unmarked child or infer trust from ordinary object properties. Supported
   source kernel: escapes remain supported; normalize their actual base kind
   for wrapper recognition without widening accepted escape grammar.
3. For genuine normal export/async declaration wrappers, examine ONLY the
   actual consumed first payload child, recursively applying dispatch to that
   child. Export names lists, reexports and arbitrary tail arguments introduce
   no new local bindings. Source/actual lowered function/class/bind declarations
   expose their enclosing names; parameter/body/branch names do not escape.
   Async exposes a supported named function/generator declaration, while
   anonymous arrow/lambda/function-expression bodies introduce no outer names.
4. Handle default export separately. Actual direct named function/generator/
   class declarations (including supported async function wrappers) in its
   default VALUE slot produce a local binding in the emitted ESM and must
   supply that declaration's name. Check the direct emitted declaration kind;
   do not walk arbitrary default-expression descendants. A conditional default
   value containing a named function is an expression-local name and does NOT
   hoist. Anonymous defaults and exported existing values introduce no name.
   The default slot is args[1], unlike normal export's args[0]. These are facts
   of current writer output, not a new export syntax or broad writer repair.
5. Native shared query lives beside the resolver's existing enclosing-kind
   filter and is used by resolver sequence/clause/member transitions, every
   pass2 top/body/class/sequence transition, D2 sequence/ref transitions, and
   shadow_seq/shadow_paths. Preserve span/kind in shadow diagnostics and only
   report actual declarations. Remove competing dispatch adapters/name helpers
   from actual consumers; keep only necessary structural projections/tests.
   Evaluate with incoming scope before adding this result's declarations.
6. Public shared query lives in binding.js, which already imports isKernel.
   Export one private helper for expander-core to project names; its D2
   walkSequenceReturning uses the same query. This new deep-module export is
   an explicit S06 API-audit input, not a new JSR entrypoint. Avoid importing
   expander back into binding.js or duplicating formHead policy. Retain existing
   completion roles, explicit result slots, per-occurrence ownership and exact
   kernel/private/host/Reflect identities; no re-expansion or additional macros.
