# CDC retrospective — native clause scope

This finite I2 follow-up reached independent acceptance at
`b5c22b63`. Luna 6 High authored source and Sol 6.1 High owned
readiness, review and independent execution. The
[verification](cdc-verification.md) preserves actual observations
and limitations.

The initial fixture design underestimated two existing frontend
routes. I chose a genuine `do` guard and nested `kernel:object`
because their language roles were appropriate. Before the target
runtime failure could be observed, the old native module emitted
both as invalid or unresolved calls. The public reserved-name
walk also falsely interpreted F1's guard as a binder. The isolated
helper and JSON.parse preserved the exact selection oracles.
The old and current generated bytes showed both underlying
clause defects and distinguished these separate carryovers.

Static review of the first source freeze found a guard lint
scope that used a direct subtree check rather than the established
single-slot sequence, and an avoidable ordinary classifier
occurrence allocation. The next freeze applies the existing
scope/capture patterns without changing fixture oracles. The
same borrowed clause adapter held across the three consumers and
both independent runtime cases.

The CC's named-path receipts did not retain all required exact
config-ancestor probes, although their real commands and pins
survived. The independent replay checked those names before
launch, with the same effective cache and fixture constraints.
For the next comparable assignment, inspect named config paths
as part of the first recorded launch preparation rather than
using a directory-only preflight. Use the same generated-module
review that exposed both unintended fixture paths. This is an
observed workflow limitation, without a comparative model claim.
