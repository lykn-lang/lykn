## Follow-through and recommendations

The [S02 recommendations](../slice02-native-binding-discards/cdc-retrospective.md)
were adopted in S03 preparation: actual whitelist admission, backend-specific
catch grammar, native/staged refresh and effects controls were explicit. They
prevented importing a blanket native rejection into public groups, but did not
prevent the child/layout/unmarked-region mistakes. Retain the recommendations
and refine the author check: trace an actual source entrance through resolution,
preparation, scope plan, writer and runtime for each materially different route.
Root owns this check when preparing S04; it is not a new investigation or a
requirement to replay every historical specimen.

For future tests, root and reviewer should name which producer the input enters
and the plausible wrong implementation it rejects. Use differing foreign/live
values, real runtime error classes, exact namespace keys and protocol effects.
When claiming a formerly untested path is covered, check its input spelling and
mode before launching full gates. Observe whether the next slice avoids another
escaped-only proof or excerpt-matching false pass; do not infer effectiveness
from correction counts alone.

Preserve source-first independent review before expensive aggregate gates.
Held30 and3d were returned without running those gates independently, while
retaining new8 success and exact counterexamples. This supports that specific
ordering decision; it does not establish a measured productivity improvement.
Retain the same source/build ownership and exact-path commit discipline.

Three refinements here do not establish that the new arc decomposition reduced
effort compared with retired22: scope, preparation and exposure differ and total
cost was not measured. No motive or model limitation is inferred. The observed
mistakes include author, implementer and reviewer contributions.
